# Re-verification on silica-999936 (2026-11-05)

`binaries/silica-compiler` now points at `silica-999936-macos-applesilicon` (chunk 15, phases 0 to 8: stack memory model,
state area, region checker, FFI retention). The numbers count down, so 999936 is newer than the 999939 of the
2026-11-04 re-run. macOS Apple Silicon only. Silica was not changed. `tools/silica.generation` had been left at 999977
and now names 999936.

**Result: all 65 trials green and the kit tests pass**, after the changes below. Before them 7 leaves failed to build or
run.

## What was found

- **SD-27, SD-28, SD-29** are new (silica-defects.md). SD-28 has a BEES-side remedy (build the new state inside the
  behaviour); SD-27 and SD-29 do not.
- **SD-27 matters to the design.** Keeping a term in actor state means replacing a region each message (S6), which can
  never be proven released, so every term-holding actor pays the fallback. Until it is fixed, a compiled `gen_server`
  with a term state is quadratic in its message count.
- **SD-26 is still open.** SD-23, SD-24 and SD-25 behave as before (their goldens did not change). `Recreatable`
  (Silica chunk 13) is still not implemented, so the receive path stays blocked (M0). Timers and clocks exist
  (D33). Monitors, `call_with_timeout`, `register`/`whereis`/`unregister` and the adapter defects Silica lists as open
  were not re-tested here.
- **The harness hid failures.** A leaf that failed to build kept its old `.integrate_counts`, so the summary read
  "0 failed" while two leaves had not built. `trials/Makefile` now removes the counts first and counts a leaf with no
  result as a failure.
