# Silica defects found while building BEES

Findings about the Silica toolchain: defects and surprises in the fixed-point compiler and
runtime. BEES never fixes them in Silica (AI_POLICY.md: a person files and lands each one); the
trial named here is the reproducer, and `trials/silica_defects/` holds the ones with their own
program. A BEES-side workaround is recorded only where it keeps to the BEES design; where it would
not, the row says what decision is needed. Compiler generation is in `tools/silica.generation`.

| # | Found | What | Reproducer | BEES workaround |

| SD-1 | 2026-09-17 | A cross-module call with **too many** arguments compiles. `answer/1` called as `mod@answer(1, 2)` passes; too few arguments is rejected (E2005), as in Silica's own `qualified_call_wrong_arg_count_trial`. Same on `silica-999977`, `silica-999982` and `silica-gen2`. | `trials/r01_harness/fail_wrong_arity.silica` (uses too few arguments so it fails as intended; the comment records the too-many case) | None needed; noted so that a BEES trial never relies on the compiler catching extra arguments. |

| SD-8 | 2026-09-17 | `cast()` to a behaviour that returns `(:reply, R, S)` (call-only, §16.2.6.1) faults at run time inside the behaviour when the state is a record or tuple (`[silica] fault … addr=0x…06`); with an `int64` state it silently works. | SD-9 | 2026-09-17 | **A `call` whose callee dies returns the zero value of the reply type** (`0` for `int64`), indistinguishable from a genuine reply; the same for a call to an already-dead actor. | SD-11 | 2026-09-17 | `write_buf` into a `buf(L, normal, uint8, N)` with a **function call as the value argument** faults at run time; binding the call's result first works, and an `int64` buffer with a call argument works. | `trials/silica_defects/sd11_write_buf_uint8_call_argument.silica` | Bind the byte first. | SD-12 | 2026-09-17 | **Tail recursion is not compiled to a jump:** a self-call in tail position is `BL`, so a 20,000,000-iteration accumulator loop overflows a 256 MB stack. `sir_recursion_strategy.md` says tail recursion costs no stack. | `trials/silica_defects/sd12_tail_recursion_grows_stack.silica` | None that removes it: every compiled loop is bounded by the actor's stack within one dispatch. | SD-13 | 2026-09-17 | A float64 binding compared with a **float literal** (`v < 0.0`) is a type mismatch (E2003); comparing with a binding that holds the literal works, and literals are fine in arithmetic. | `trials/silica_defects/fail_sd13_float_literal_in_comparison.silica` | Bind the literal first. | SD-14 | 2026-09-17 | **Float64 code generation:** (a) a float parameter is clobbered by a sequence binding or a call (`b3(1.5, 2.0)` prints 4.5 not 5.0; `b4(1.5)` prints 4.0 not 3.0); (b) a float literal in a `case` arm of a non-main function is emitted as `L_f64_-1` and the assembler fails; (c) an int64 comparison inside a sequence of a float64-returning function is emitted as `MOV X9, D0` and the assembler fails. | SD-16 | 2026-09-17 | `print_bool` inside a `case`-arm block `{ … }` emits `BL L_pb_helper` / `L_pb_true` but never the helper, so the assembler fails ("local symbol not defined"); at sequence top level it works. | The S4 note §3 (source in the note's history); `sd14`'s class | Print from a top-level sequence. | SD-17 | 2026-09-17 | **FFI workers cannot live in a library unit.** A unit whose worker behaviour holds an `external_danger` sequence but whose `spawn_dangerous` site is in another unit fails with E4041; an exported installer that spawns the worker fails at its caller with E4042 (no `dangerous_*` call outside a worker). | SD-20 | 2026-09-17 | A function returning `(region(L, normal), T)` (the "return the handle with the reference" shape from §12.1.4 and the region tutorial) **crashes when called on an actor thread**: exit 70 with no report, or a fault whose pc equals its address. | SD-21 | 2026-09-17 | **Every call of a function that returns an aggregate (record or tuple) leaks stack** for the life of the actor: ~32 bytes per call (~4 for a one-field record), never released between dispatches, until the 8 MB actor stack guard (`[silica] fault … addr = stack base + 0x800000`). 100,000 messages × 10 record-returning calls fault; 100 messages × 1,000 calls per message are fine; `int64` and single-reference returns never leak. | `trials/silica_defects/sd21_aggregate_return_leaks_stack.silica` | `bees_term` and `bees_recv` return single references (`ref?(L, normal, rec)`) everywhere; the heap is passed in as a record; message builders still return a record once per send.
